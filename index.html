Getting started

print()

Why it exists

The only way you can see what your code did. Nothing you write means anything until you print it, and most debugging is nothing more clever than printing the thing you doubt.

In short

Puts something on the screen. Several things separated by commas get a space between them.

Code
print("Hello, Data Analytics")
print("TAP", "Academy")
print(10 + 5)
Output
Hello, Data Analytics TAP Academy 15

Comments

In short

Anything after a # on a line is ignored by Python. It is a note to the next person reading it, who is usually you in three weeks.

Code
# this whole line is ignored
salary = 50000      # so is everything after the hash
print(salary)
Output
50000

Variables

In short

A name pointing at a value. Use = to make it point. You can point it at something else later, and you do not have to say what type it is.

Code
name = "Priya"
salary = 50000
print(name, "earns", salary)

salary = 62000      # the old value is gone
print(salary)
Output
Priya earns 50000 62000

Several variables at once

In short

One line can set up more than one name.

Code
a, b, c = 10, 20, 30
print(a, b, c)

x = y = 5           # both point at the same 5
print(x, y)
Output
10 20 30 5 5

Naming rules

In short

Letters, digits and underscores. It cannot start with a digit, it cannot contain a space or a dash, and it is case sensitive, so Salary and salary are two different variables.

Code
emp_name = "Arun"        # good
emp2 = "Kavita"          # good
_total = 100             # allowed

Salary = 1

input()

Why it exists

The first time your program depends on somebody else. Everything about reading a CSV later is the same idea: the data comes from outside, and you cannot assume what it is.

In short

Stops and waits for the person to type something, then hands it back. The text in the brackets is the prompt. What somebody types is not part of the output, so in the box below the prompt and the next line of output run together; on your own screen you would see Sharath on the end of the first line.

Code
name = input("Your name: ")       # typed: Sharath
print("Welcome,", name)
Output
Your name: Welcome, Sharath

input() always gives you text

In short

Whatever is typed arrives as a string, even if it looks like a number. Wrap it in int() or float() before you do maths with it. 30 typed twice gives 3030, which is the clearest symptom there is.

Code
age = input("Age: ")              # typed: 30
print(type(age))
print(age + age)                  # text joined, not added

age = int(input("Age again: "))   # typed: 30
print(type(age))
print(age + age)                  # now it adds
Output
Age: <class 'str'> 3030 Age again: <class 'int'> 60

sep and end

In short

sep changes what goes between the items. end changes what goes at the end instead of a new line.

Code
print("2026", "11", "26", sep="-")
print("no new line here...", end=" ")
print("same line")
Output
2026-11-26 no new line here... same line

None

Why it exists

Every real dataset has holes in it. None is what a hole looks like in plain Python, and pandas calls the same idea NaN. Knowing it is not zero saves you from averaging rubbish.

In short

The value that means "nothing here yet". It is not 0 and it is not an empty string.

Code
manager = None
print(manager)
print(type(manager))
print(manager == 0)
print(manager is None)     # this is how you check for it
Output
None <class 'NoneType'> False True

Changing type on purpose

In short

int(), float(), str() and bool() make a new value of that type. The original is untouched.

Code
print(int("42") + 1)
print(float("3.5") + 1)
print(str(42) + "1")
print(int(9.99))           # chops the decimal off, does not round
Output
43 4.5 421 9

When a conversion is not possible

In short

int() on text that is not a number stops the program. Check before you convert.

Code
print(int("42"))
print(int("forty two"))
Output

In short

bool() on almost anything gives True. The exceptions are 0, empty text, empty containers and None.

Code

print(bool(0), bool(""), bool([]), bool(None))
Output
True True True True False False False False

Operators

Arithmetic

In short

The six you use constantly, plus // for whole-number division and % for the remainder.

Code
print(17 + 3)
print(17 - 3)
print(17 * 3)
print(17 / 3)        # true division, gives a float
print(17 // 3)       # floor division, drops the fraction
print(17 % 3)        # remainder
print(2 ** 10)       # power
Output
20 14 51 5.666666666666667 5 2 1024

% to test divisibility

In short

If the remainder is 0 it divides exactly. This is the standard even-or-odd test.

Code
n = 24
print(n % 2)
print(n % 2 == 0)        # even?
print(25 % 2 == 0)
Output
0 True False

Assignment operators

In short

Shorthand for "take what is there, change it, put it back".

Code

print(total)
total -= 20
print(total)
total *= 2

Comparison

In short

Six of them, and every one hands back True or False. Note == for "is it equal" against = for "make it equal".

Code
print(50000 == 50000)
print(50000 != 50000)
print(50000 > 40000)
print(50000 < 40000)
print(50000 >= 50000)
print(50000 <= 40000)
Output
True False True False True False

Logical: and, or, not

In short

and needs both sides True. or needs one. not flips it.

Code
salary = 70000
dept = "Tech"
print(salary > 60000 and dept == "Tech")
print(salary > 90000 and dept == "Tech")
print(salary > 90000 or dept == "Tech")
print(not salary > 90000)
Output
True False True True

Membership: in, not in

In short

Asks whether something sits inside a string, list, tuple, set or dictionary.

Code
depts = ["Sales", "Tech", "HR"]
print("Tech" in depts)
print("Legal" in depts)
print("Legal" not in depts)
print("ech" in "Tech")        # works on text too
Output
True False True True

Identity: is, is not

In short

is asks "are these the very same object", == asks "do these hold the same value". Different questions, and they can disagree.

Code
a = [1, 2, 3]
b = [1, 2, 3]
c = a
print(a == b)        # same contents
print(a is b)        # but two separate lists
print(a is c)        # c is just another name for a
Output
True False True

Bitwise

In short

Works on the binary form of whole numbers. You will rarely need it in analytics, but it was on the operators list, so here it is.

Code
print(bin(12), bin(10))
print(12 & 10)       # AND  -> 1000
print(12 | 10)       # OR   -> 1110
print(12 ^ 10)       # XOR  -> 0110
print(12 << 1)       # shift left, doubles it
print(12 >> 1)       # shift right, halves it
Output
0b1100 0b1010 8 14 6 24 6

Precedence

In short

Python does ** first, then * / // %, then + -, then comparisons, then not, then and, then or. Brackets beat all of it, and brackets cost nothing.

Code
print(2 + 3 * 4)
print((2 + 3) * 4)
print(10 - 2 - 3)         # left to right
print(2 ** 3 ** 2)        # but ** goes right to left
Output
14 20 5 512

Making decisions

if

Why it exists

The point where a program stops being a calculator. Every filter you will ever write in pandas is this same question asked of a whole column at once.

In short

Runs the indented block only when the condition is True. The colon and the indentation are both compulsory.

Code
salary = 70000
if salary > 60000:
    print("above sixty")
print("this always runs")
Output
above sixty this always runs

if / else

In short

One block or the other, never both.

Code
salary = 45000
if salary > 60000:
    print("above sixty")
else:
    print("sixty or below")
Output
sixty or below

if / elif / else

In short

Checked top to bottom. The first True one wins and the rest are skipped, so order matters.

Code
salary = 95000
if salary >= 100000:
    print("band A")
elif salary >= 70000:
    print("band B")
elif salary >= 40000:
    print("band C")
else:
    print("band D")
Output
band B

Order of the conditions matters

In short

Put the narrowest test first. Written the wrong way round, a later condition can never be reached.

Code
salary = 150000
if salary > 50000:
    print("wrong: everybody lands here")
elif salary > 100000:
    print("never reached")

if salary > 100000:
    print("right: narrowest first")
elif salary > 50000:
    print("not reached for 150000")
Output
wrong: everybody lands here right: narrowest first

Nested if

In short

An if inside an if. Each level is indented one step further.

Code
dept = "Tech"
salary = 90000
if dept == "Tech":
    if salary > 80000:
        print("senior tech")
    else:
        print("tech")
else:
    print("not tech")
Output
senior tech

Combining conditions instead of nesting

In short

Two levels of if joined by and say the same thing on one line, and it reads better.

Code
dept = "Tech"
salary = 90000
if dept == "Tech" and salary > 80000:
    print("senior tech")
Output
senior tech

Deciding with in

In short

Checking membership saves a chain of == tests.

Code
dept = "HR"
if dept in ["Sales", "Tech"]:
    print("revenue side")
else:
    print("support side")
Output
support side

Loops

for with range()

Why it exists

Doing the same thing to every row is the whole job. A loop is the first tool for it, and understanding it is what lets you appreciate why NumPy and pandas do it without one.

In short

range(n) counts 0, 1, 2 up to but not including n. That "not including" is where most off-by-one mistakes come from.

Code
for i in range(5):
    print(i)
Output
0 1 2 3 4

range() with start, stop and step

In short

range(start, stop) begins where you say. A third number is the step, and it can be negative.

Code
for i in range(1, 6):
    print(i, end=" ")
print()

for i in range(0, 21, 5):
    print(i, end=" ")
print()

for i in range(5, 0, -1):
    print(i, end=" ")
print()
Output
1 2 3 4 5 0 5 10 15 20 5 4 3 2 1

for over a list

In short

The cleanest loop in Python: no counter, no index, just each item in turn.

Code
depts = ["Sales", "Tech", "HR", "Legal"]
for d in depts:
    print(d)
Output
Sales Tech HR Legal

for over a string

In short

A string is a sequence, so a loop walks it one character at a time.

Code
for ch in "TAP":
    print(ch)
Output
T A P

Looping with an index

In short

When you genuinely need the position, loop over range(len(...)) and use it to reach into the list.

Code
depts = ["Sales", "Tech", "HR"]
for i in range(len(depts)):
    print(i, depts[i])
Output
0 Sales 1 Tech 2 HR

while

In short

Keeps going as long as the condition stays True. Something inside the loop has to change, or it never stops.

Code
n = 5
while n > 0:
    print(n, end=" ")
    n -= 1          # without this line it runs forever
print()
print("done")
Output
5 4 3 2 1 done

for or while

In short

Use for when you know how many times. Use while when you do not, and the loop runs until something becomes true.

Code
# known count -> for
total = 0
for i in range(1, 11):
    total += i
print("1 to 10 adds to", total)

# unknown count -> while
balance = 1000
years = 0
while balance < 1500:
    balance = balance * 1.10
    years += 1
print("doubled past 1500 after", years, "years")
Output
1 to 10 adds to 55 doubled past 1500 after 5 years

break

In short

Leaves the loop immediately. The rest of the items are not looked at.

Code
for d in ["Sales", "Tech", "HR", "Legal"]:
    if d == "HR":
        print("found HR, stopping")
        break
    print("checked", d)
Output
checked Sales checked Tech found HR, stopping

continue

In short

Skips the rest of this turn and goes straight to the next item. The loop carries on.

Code
for i in range(1, 8):
    if i % 2 == 0:
        continue          # skip the even ones
    print(i, end=" ")
print()
Output
1 3 5 7

pass

In short

Does nothing at all. It exists because Python refuses an empty block, so pass is the placeholder you leave while you think.

Code
for i in range(3):
    pass
print("the loop ran and did nothing")
Output
the loop ran and did nothing

Nested loops

In short

A loop inside a loop. The inner one finishes completely for every single turn of the outer one, so 3 x 3 is nine lines of work.

Code
for i in range(1, 4):
    for j in range(1, 4):
        print(i * j, end="\t")
    print()
Output
1 2 3 2 4 6 3 6 9

Running a total

In short

Start at zero outside the loop, add inside it, print after. The pattern behind every sum you will ever write.

Code
salaries = [50000, 62000, 48000, 91000]
total = 0
for s in salaries:
    total += s
print("total", total)
print("average", total / len(salaries))
Output
total 251000 average 62750.0

Counting what matches

In short

Same shape, but the counter only moves when the condition holds.

Code
salaries = [50000, 62000, 48000, 91000, 120000]
count = 0
for s in salaries:
    if s > 60000:
        count += 1
print(count, "of", len(salaries), "earn above 60000")
Output
3 of 5 earn above 60000

Finding the biggest yourself

In short

Worth writing once by hand, because it shows you what max() is actually doing.

Code
salaries = [50000, 62000, 48000, 91000]
biggest = salaries[0]
for s in salaries:
    if s > biggest:
        biggest = s
print(biggest)
print(max(salaries))     # the short way
Output
91000 91000

Functions

def and calling it

Why it exists

The cure for copy and paste. Write the logic once, give it a name, and every fix you make afterwards lands everywhere it is used.

In short

def writes the function down. Nothing happens until you call it by name with brackets, and you can call it as often as you like.

Code
def greet():
    print("Welcome to TAP Academy")

greet()
greet()
Output
Welcome to TAP Academy Welcome to TAP Academy

Parameters and arguments

In short

The name in the def line is the parameter. The value you hand over when you call it is the argument.

Code
def greet(name):          # name is the parameter
    print("Welcome,", name)

greet("Priya")            # "Priya" is the argument
greet("Arun")
Output
Welcome, Priya Welcome, Arun

More than one parameter

In short

Comma separated, and by default they are matched by position, so the order you pass them in is the order they are read.

Code
def pay(name, salary):
    print(name, "earns", salary)

pay("Kavita", 48000)
pay(48000, "Kavita")       # same call, wrong order, nonsense result
Output
Kavita earns 48000 48000 earns Kavita

return

In short

Hands a value back to whoever called it, so you can store it or use it in a bigger sum. print() only shows something; return gives it to you.

Code
def add(a, b):
    return a + b

answer = add(10, 20)
print(answer)
print(add(1, 2) * 10)      # usable in an expression
Output
30 30

print inside a function is not the same as return

In short

A function that prints gives you None. You cannot do arithmetic with it.

Code
def shows(a, b):
    print(a + b)

def gives(a, b):
    return a + b

x = shows(2, 3)
print("shows gave back:", x)
y = gives(2, 3)
print("gives gave back:", y)
Output
5 shows gave back: None gives gave back: 5

return ends the function

In short

Nothing after a return runs. That makes it useful for stepping out early.

Code
def band(salary):
    if salary >= 100000:
        return "A"
    if salary >= 60000:
        return "B"
    return "C"

print(band(150000), band(70000), band(30000))
Output
A B C

Returning more than one value

In short

Separate them with commas. What comes back is a tuple, and you can unpack it into separate names.

Code
def stats(nums):
    return min(nums), max(nums), sum(nums) / len(nums)

lo, hi, avg = stats([50000, 62000, 48000, 91000])
print(lo, hi, avg)
print(stats([1, 2, 3]))        # as one tuple
Output
48000 91000 62750.0 (1, 3, 2.0)

Default parameter

In short

Give the parameter a value in the def line and the caller can leave it out. Any parameter with a default must come after the ones without.

Code
def pay(name, salary=50000):
    print(name, salary)

pay("Priya")                # default used
pay("Priya", 90000)         # default overridden
Output
Priya 50000 Priya 90000

Naming the arguments when you call

In short

Pass them as name=value and the order stops mattering. This is how you will call almost every pandas function.

Code
def emp(name, dept, city):
    print(name, "|", dept, "|", city)

emp("Arun", "Tech", "Chennai")
emp(city="Chennai", name="Arun", dept="Tech")      # same result
Output
Arun | Tech | Chennai Arun | Tech | Chennai

A function that calls another

In short

Normal and good. Small functions that do one thing each, stacked up.

Code
def is_senior(salary):
    return salary > 80000

def label(name, salary):
    if is_senior(salary):
        return name + " (senior)"
    return name

print(label("Arun", 91000))
print(label("Kavita", 48000))
Output
Arun (senior) Kavita

Local variables

In short

A name created inside a function exists only while that function runs. Outside it, Python has never heard of it.

Code
def calc():
    inside = 99
    print("inside the function:", inside)

calc()
print(inside)
Output
inside the function: 99 NameError: name 'inside' is not defined

Reading a variable from outside

In short

A function can read a name defined outside it. Assigning to that name inside the function makes a new local one instead, and the outer value is left alone.

Code
rate = 0.10                  # defined outside

def bonus(salary):
    return salary * rate     # read from outside, fine

print(bonus(50000))

def reset():
    rate = 0.50              # makes a NEW local rate
    print("inside:", rate)

reset()
print("outside is untouched:", rate)
Output
5000.0 inside: 0.5 outside is untouched: 0.1

How many characters, spaces included.

Code

Output
a y P

Index out of range

In short

Ask for a position that does not exist and Python stops. There is no silent blank.

Code

Slicing

Why it exists

The same two-dots notation runs through the entire course. Lists slice like this, NumPy arrays slice like this, and df.iloc slices like this. Learn it once here.

In short

name[start:stop] gives you everything from start up to but not including stop. Leave a side out and Python assumes the beginning or the end.

Code
name = "TAP Academy"
print(name[0:3])
print(name[4:11])
print(name[:3])         # from the start
print(name[4:])         # to the end
print(name[:])          # the whole thing
Output
TAP Academy TAP Academy TAP Academy

Slicing with a step

In short

A third number takes every nth character. A step of -1 reverses the string, which is the standard trick.

Code
s = "ABCDEFGH"
print(s[0:8:2])
print(s[::3])
print(s[::-1])          # reversed
Output
ACEG ADG HGFEDCBA

Strings cannot be changed

In short

You cannot assign to one character. Every string method hands you back a new string and leaves the original exactly as it was.

Code
name = "priya"
name[0] = "P"
Output
TypeError: 'str' object does not support item assignment

So reassign instead

In short

Catch what the method gives back. If you do not store it, nothing appears to happen.

Code
name = "priya"
name.upper()                 # result thrown away
print(name)

name = name.upper()          # result kept
print(name)
Output
priya PRIYA

Joining and repeating

In short

Plus glues two strings together. Star repeats one. Plus will not mix text and numbers.

Code
first = "Priya"
last = "Nair"
print(first + " " + last)
print("-" * 20)
print("Total: " + str(50000))      # str() needed
Output
Priya Nair -------------------- Total: 50000

upper, lower, title, capitalize

In short

Case changes. Lowercasing both sides is how you compare text safely.

Code
s = "data ANALYTICS course"
print(s.upper())
print(s.lower())
print(s.title())
print(s.capitalize())
print("TECH".lower() == "tech")
Output
DATA ANALYTICS COURSE data analytics course Data Analytics Course Data analytics course True

strip, lstrip, rstrip

In short

Removes whitespace from the ends, not the middle. The first thing you do to anything typed by a human.

Code
s = "   Chennai   "
print("[" + s + "]")
print("[" + s.strip() + "]")
print("[" + s.lstrip() + "]")
print("[" + s.rstrip() + "]")
print("[" + "xxChennaixx".strip("x") + "]")     # strip any character
Output
[ Chennai ] [Chennai] [Chennai ] [ Chennai] [Chennai]

replace

In short

Swaps every occurrence. Give it a third number to limit how many.

Code
s = "Sales,Tech,Sales,HR"
print(s.replace("Sales", "Revenue"))
print(s.replace("Sales", "Revenue", 1))
print(s.replace(",", " | "))
Output
Revenue,Tech,Revenue,HR Revenue,Tech,Sales,HR Sales | Tech | Sales | HR

split

Why it exists

This is what reading a CSV is underneath. One line of a file, split on the comma, is one row of your table.

In short

Cuts a string into a list. No argument splits on whitespace; give it a character and it splits on that.

Code
s = "Priya,Tech,Chennai"
print(s.split(","))
print("one two three".split())
parts = s.split(",")
print(parts[1])
Output
['Priya', 'Tech', 'Chennai'] ['one', 'two', 'three'] Tech

join

In short

The opposite of split. The string you call it on is the glue that goes between the items.

Code
parts = ["Priya", "Tech", "Chennai"]
print(",".join(parts))
print(" | ".join(parts))
print("".join(["a", "b", "c"]))
Output
Priya,Tech,Chennai Priya | Tech | Chennai abc

find and index

In short

Both give the position of the first match. find returns -1 when there is nothing; index stops the program instead.

Code
s = "data analytics"
print(s.find("analytics"))
print(s.find("python"))         # -1, no error
print(s.index("analytics"))
Output
5 -1 5

count

In short

How many times something appears, without overlaps.

Code
s = "Sales,Tech,Sales,HR,Sales"
print(s.count("Sales"))
print(s.count(","))
print(s.count("z"))
Output

True or False, no position. The usual way to spot a file type or a prefix.

Encapsulation

What it means

Why it exists

Without it, anyone can set a salary to minus five lakh. With it, every change has to go through a method you wrote, so you get to say what counts as valid.

            self.__balance += amount

        return self.__balance

a = Account(1000)
a.deposit(500)
a.deposit(-9999)                        # refused by the method

Output
1500

In short

Inheritance

Parent and child

Why it exists

Write the common part once. Change it once. The alternative is the same twenty lines pasted into five classes, and a bug fixed in only four of them.

In short

Put the parent class in brackets after the child name and the child gets everything the parent has, without a line of it being copied.

Code
class Employee:
    def __init__(self, name):
        self.name = name

    def show(self):
        print("employee:", self.name)

class Manager(Employee):          # Manager inherits from Employee
    pass

m = Manager("Priya")
m.show()                          # a method it never defined
print(m.name)
Output
employee: Priya Priya

The child adds its own

In short

Everything from the parent, plus whatever is new. The parent knows nothing about the child.

Code
class Employee:
    def __init__(self, name):
        self.name = name

    def show(self):
        print("employee:", self.name)

class Manager(Employee):
    def approve(self, what):
        print(self.name, "approved", what)

m = Manager("Priya")
m.show()
m.approve("leave request")
Output
employee: Priya Priya approved leave request

super()

In short

When the child writes its own __init__ the parent one stops running. super().__init__() calls it by hand so the parent still does its share.

Code
class Employee:
    def __init__(self, name):
        self.name = name
        print("Employee __init__ ran")

class Manager(Employee):
    def __init__(self, name, team_size):
        super().__init__(name)        # run the parent's setup first
        self.team_size = team_size

m = Manager("Priya", 4)
print(m.name, m.team_size)
Output
Employee __init__ ran Priya 4

Forgetting super()

In short

Leave it out and whatever the parent set up never happens, so the attribute is simply not there.

Code
class Employee:
    def __init__(self, name):
        self.name = name

class Manager(Employee):
    def __init__(self, team_size):
        self.team_size = team_size    # parent __init__ never ran

m = Manager(4)
print(m.team_size)
print(m.name)
Output

In short

Give the child a method with the same name and the child version wins. The parent version is still there for the parent.

Polymorphism

One name, several behaviours

Why it exists

It is what lets you write one loop that handles a mixed pile of objects. The loop does not ask what anything is; it just calls the method and trusts each class to behave.

In short

The word means many forms. The same method name does the right thing for whichever class the object happens to be.

Code

        print("Woof")

    def speak(self):
        print("Meow")

for animal in [Dog(), Cat(), Dog()]:
    animal.speak()
Output
Woof Meow Woof

Duck typing

In short

Python never checks the class. If the object has the method, the call works. If it walks like a duck, it is treated as a duck.

make_it_speak(Dog())
make_it_speak(Car())

Woof Vroom

Overriding is polymorphism

In short

The parent promises a method, every child keeps the promise its own way, and the caller does not need to know which is which.

Method overloading does not exist in Python

In short

Two methods with the same name do not coexist: the second definition replaces the first. Use a default parameter to get the same effect.

Code
class Calc:
    def add(self, a, b):
        return a + b

    def add(self, a, b, c):          # this one wins, the first is gone
        return a + b + c

print(Calc().add(1, 2, 3))

class Better:
    def add(self, a, b, c=0):        # one method, both uses
        return a + b + c

print(Better().add(1, 2))
print(Better().add(1, 2, 3))
Output
6 3 6

Abstraction

What it means

Why it exists

Every library you will use is this. You call read_csv and a thousand lines of file parsing happen that you never read. Writing your own classes the same way is the skill.

In short

Showing what something does and hiding how it does it. You call the method; you do not need to know what is inside it.

Code
class Card:
    def pay(self, amount):
        self.__check_balance()          # hidden steps
        self.__contact_bank()
        print("paid", amount)

    def __check_balance(self):
        print("(checking balance)")

    def __contact_bank(self):
        print("(contacting bank)")

Card().pay(500)
Output
(checking balance) (contacting bank) paid 500

An abstract class

In short

Inherit from ABC and mark a method with @abstractmethod and you have written a rule: any child must provide that method.

Code
from abc import ABC, abstractmethod

class Shape(ABC):
    @abstractmethod
    def area(self):
        pass

class Square(Shape):
    def __init__(self, side):
        self.side = side

    def area(self):
        return self.side ** 2

print(Square(5).area())
Output
25

An abstract class cannot be built

In short

That is the point of it. It exists to be inherited from, not to be used directly.

Code
from abc import ABC, abstractmethod

class Shape(ABC):
    @abstractmethod
    def area(self):
        pass

s = Shape()
Output
TypeError: Can't instantiate abstract class Shape without an implementation for abstract method 'area'

The child must implement it

In short

Skip the abstract method in the child and the child cannot be built either. The error arrives early, which is what you want.

Code
from abc import ABC, abstractmethod

class Shape(ABC):
    @abstractmethod
    def area(self):
        pass

class Circle(Shape):
    pass                     # area() never written

c = Circle()
Output
TypeError: Can't instantiate abstract class Circle without an implementation for abstract method 'area'

Abstraction against encapsulation

In short

Encapsulation hides the data. Abstraction hides the work. Both are about showing less, but they hide different things.

Code
class Payroll:
    def __init__(self, salary):
        self.__salary = salary          # encapsulation: data hidden

    def monthly_slip(self):             # abstraction: work hidden
        return self.__net()

    def __net(self):
        return round(self.__salary / 12 * 0.9, 2)

print(Payroll(600000).monthly_slip())
Output
45000.0

What kind of column is itDay 2

The four scales

Why it exists

The scale of a column decides which calculations are legal on it. This is the most common beginner mistake and the computer will not stop you making it.

In short

NOMINAL: names, no order. ORDINAL: there is an order but the gaps are not equal. INTERVAL: equal gaps but no true zero. RATIO: equal gaps and a real zero, so ratios make sense.

print("NOMINAL   department :", df['department'].unique())
print("ORDINAL   education  :", df['education'].unique())
print("INTERVAL  join_date  :", df['join_date'].head(2).values)
print("RATIO     salary     :", df['salary'].head(2).values)
print()
print("the test for RATIO: does zero mean none of it?")
print("   salary 0  = no salary at all   -> ratio")
print("   year 0    = not 'no time'      -> interval")
Output
NOMINAL department : ['HR' 'Marketing' 'Tech' 'Sales'] ORDINAL education : ['Masters' 'Diploma' 'Bachelors'] INTERVAL join_date : ['2018-01-03' '2024-07-02'] RATIO salary : [47764. 86052.] the test for RATIO: does zero mean none of it? salary 0 = no salary at all -> ratio year 0 = not 'no time' -> interval

Samples and populationsDay 3

Parameter vs statistic

Why it exists

Two words that get used as if they mean the same thing. Interviewers ask this directly, because it shows whether you know what you are actually computing.

In short

A PARAMETER describes the population and you almost never know it. A STATISTIC describes your sample and is the only thing you can compute. Inferential statistics is using the second to guess the first.

Code
print("PARAMETER  mu     - the population average :", round(sal.mean()))
print("STATISTIC  x-bar  - this sample average    :", round(sal.sample(30, random_state=1).mean()))
print()
print("at work you only ever see the second line.")
print("we can see both here only because this file IS our population.")
Output
PARAMETER mu - the population average : 95648 STATISTIC x-bar - this sample average : 70032 at work you only ever see the second line. we can see both here only because this file IS our population.

More data does not fix bias

Why it exists

The most expensive mistake in sampling, and the reason a huge survey can still be wrong. Remember it as a story rather than a formula.

In short

In 1936 the Literary Digest asked ten million people, got 2.4 million replies, and still called the election wrong because of WHO they asked. A 50,000-person honest sample beat them. Size fixes noise; only method fixes bias.

Code
print("an honest sample of 30:")
print("   ", round(sal.sample(30, random_state=1).mean()))
print()
print("a BIASED sample - every Tech employee, 49 people:")
print("   ", round(df[df['department'] == 'Tech']['salary'].mean()))
print()
print("the truth:", round(sal.mean()))
print("the biased one used more people and landed further away.")
Output
an honest sample of 30: 70032 a BIASED sample - every Tech employee, 49 people: 189754 the truth: 95648 the biased one used more people and landed further away.

Population vs sample

Why it exists

You will never measure everybody. Every number you report at work comes from a sample.

In short

The POPULATION is everyone you care about. A SAMPLE is the few you actually measured. Greek letters for the population, Roman for the sample.

Code
print("population mean  mu     :", round(pop.mean()))
print("sample mean      x-bar  :", round(pop.sample(30, random_state=1).mean()))
print()
print("we can only ever compute the second one. the first is what we want.")

population mean mu : 69630 sample mean x-bar : 70006 we can only ever compute the second one. the first is what we want.

How to build a sample

Why it exists

A biased sample gives a confident wrong answer, and more data does not fix it.

In short

SIMPLE RANDOM: everyone equally likely. STRATIFIED: split into groups, sample each in proportion. SYSTEMATIC: every nth one. CLUSTER: pick whole groups. The first two are the ones you will use.

Code
print("SIMPLE RANDOM - everyone equally likely")
print("   ", round(pop.sample(30, random_state=1).mean()))
print()
print("STRATIFIED - take some from every group on purpose")
for name, g in df.groupby('department'):
    print("   ", name, "->", round(g['salary'].sample(8, random_state=1).mean()))
print()
print("SYSTEMATIC - every 10th row.   CLUSTER - pick whole offices, survey all of them.")
print("CONVENIENCE - whoever is nearby. fastest, and the one that goes wrong.")
Output

Bias vs noise

Why it exists

They look the same on a screen and need completely different fixes.

In short

NOISE is random scatter - it shrinks with more data. BIAS is being consistently off in one direction - more data just makes you confidently wrong. Only a better sampling method fixes bias.

Code
print("noise: 5 honest samples, all different, all near the truth")
for s in (1,2,3):
    print("   ", round(pop.sample(30, random_state=s).mean()))
print()
print("bias: only surveying Tech")
print("   ", round(df[df['department']=='Tech']['salary'].mean()),

The Central Limit TheoremDay 10

The problem it solves

Why it exists

This is the hinge. Everything after it - intervals, tests, A/B - is this applied.

In short

One sample can be badly wrong, and you only ever get one. So how can any number be trusted? The answer is that the PATTERN of sample averages is completely predictable, even when the data is not.

Code
print("five samples of 30 from the SAME column:")
for s in (1,2,3,4,5):
    print("   ", round(sal.sample(30, random_state=s).mean()))
print("the truth:", round(sal.mean()))
print()
print("if I take only ONE of these, which am I holding? no way to know.")
Output
five samples of 30 from the SAME column: 70032 244006 239817 65149 235447 the truth: 95648 if I take only ONE of these, which am I holding? no way to know.

What the theorem says

Why it exists

It lets you say how wrong your one sample might be, without ever taking a second one.

In short

Take the average of a sample and repeat. Those averages form their own shape. The BIGGER each sample, the CLOSER that shape gets to a normal bell curve, centred on the true mean - whatever shape the original data had.

Code
means = []
for i in range(1000):
    means.append(pop.sample(30, replace=True, random_state=i).mean())
means = pd.Series(means)
print("average of the 1000 averages:", round(means.mean()), " (truth 69630)")
print("spread of those averages    :", round(means.std()))
print("skew of those averages      :", round(means.skew(), 2), " -> near 0 = normal")
Output
average of the 1000 averages: 69680 (truth 69630) spread of those averages : 3026 skew of those averages : 0.09 -> near 0 = normal

Bigger samples, not more samples

Why it exists

The most common wrong takeaway. Repeating a small sample does not help.

In short

Normal means skew 0, so 'becomes normal' means 'skew heads to zero'. It is the SIZE of each sample that drives it down - the number of repeats only makes the picture smoother.

Code
def skew_of(n, reps):
    means = []
    for i in range(reps):
        means.append(sal.sample(n, replace=True, random_state=i).mean())
    return round(pd.Series(means).skew(), 2)

print("raw column skew:", round(sal.skew(), 2))
print()
print("BIGGER samples fix it:")
for n in (30, 100, 500): print("   ", n, "->", skew_of(n, 2000))
print()
print("MORE samples do not:")
for r in (200, 5000, 20000): print("   ", r, "samples of 30 ->", skew_of(30, r))
Output
raw column skew: 14.06 BIGGER samples fix it: 30 -> 2.52 100 -> 1.41 500 -> 0.77 MORE samples do not: 200 samples of 30 -> 2.21 5000 samples of 30 -> 2.52 20000 samples of 30 -> 2.51

Standard error

Why it exists

The number that tells you how much to trust your own average. Nothing else does this.

In short

The standard deviation OF AVERAGES, rather than of people. It shrinks as the sample grows: sigma / sqrt(n). A standard deviation does not shrink with more data; a standard error does.

Code
sigma = pop.std()
print("standard deviation of PEOPLE :", round(sigma), " (never changes)")
print()
for n in (5, 30, 100, 400):

Confidence intervalsDay 11

What a confidence interval is

Why it exists

It turns 'the average is X' - which you cannot support - into something you can defend.

In short

Your sample's average, plus and minus a margin. margin = 1.96 x standard error. The result is reported as 'X, give or take Y'.

Code
sample = pop.sample(100, replace=True, random_state=54)
m  = sample.mean()
se = sample.std() / math.sqrt(100)
print("sample mean    :", round(m))
print("standard error :", round(se))
print("95% interval   :", round(m - 1.96*se), "to", round(m + 1.96*se))
print("the truth      :", round(pop.mean()), " <- inside")
Output
sample mean : 72149 standard error : 1631 95% interval : 68952 to 75346 the truth : 69630 <- inside

What the 95% actually means

Why it exists

The single most common error in applied statistics. People with degrees get this wrong.

In short

WRONG: '95% chance the true mean is in my interval.' The true mean is FIXED - it is in or out, already decided. RIGHT: '95% of the intervals this METHOD produces contain the truth.' The randomness is in the interval, not in the truth.

Code
caught, truth = 0, pop.mean()
for i in range(100):
    x = pop.sample(100, replace=True, random_state=i)
    e = 1.96 * x.std() / math.sqrt(100)
    if x.mean() - e <= truth <= x.mean() + e:
        caught += 1
print(caught, "of 100 intervals contained the truth")
print()
print("the truth never moved. the INTERVAL moved.")
print("the 4 that missed did nothing wrong - that is what 95% means.")
Output
96 of 100 intervals contained the truth the truth never moved. the INTERVAL moved. the 4 that missed did nothing wrong - that is what 95% means.

It is about the AVERAGE, not the data

Why it exists

A very easy mistake that makes the interval look ten times too narrow.

In short

The interval describes where the MEAN probably sits. It does not describe where 95% of the individual values sit - that range is far wider.

Code
sample = pop.sample(100, replace=True, random_state=54)
m  = sample.mean(); se = sample.std()/math.sqrt(100)
lo, hi = m-1.96*se, m+1.96*se
print("interval for the MEAN :", round(lo), "to", round(hi))
print("share of SALARIES in that range:", round(((pop>=lo)&(pop<=hi)).mean()*100, 1), "%")
print()
print("where 95% of PEOPLE actually sit:",
      round(pop.quantile(0.025)), "to", round(pop.quantile(0.975)))
Output
interval for the MEAN : 68952 to 75346 share of SALARIES in that range: 13.2 % where 95% of PEOPLE actually sit: 39821 to 103162

The two levers

Why it exists

Both cost something. Knowing what lets you defend the sample size you chose.

In short

More CONFIDENCE makes the interval WIDER - certainty is bought with vagueness. More DATA makes it narrower, but at four times the data for twice the precision.

Code
sample = pop.sample(100, replace=True, random_state=54)
se = sample.std()/math.sqrt(100); m = sample.mean()
for lvl, z in [(90, 1.645), (95, 1.96), (99, 2.576)]:
    print(lvl, "% -> width", round(2*z*se))
print()
for n in (100, 400, 1600):
    print("n =", n, "-> width", round(2*1.96*pop.std()/math.sqrt(n)))
Output
90 % -> width 5367 95 % -> width 6395 99 % -> width 8404 n = 100 -> width 6298 n = 400 -> width 3149 n = 1600 -> width 1574

How many people do you need

Why it exists

Answers 'why do polls always ask about a thousand people' - and lets you size your own survey.

In short

Turn the margin formula inside out to give n. Use p = 0.5 because p(1-p) is largest there, so you are safe whatever the real answer is. The population size is NOT in the formula.

from math import ceil
for E_ in (0.05, 0.03, 0.01):
    n = (1.96**2 * 0.5 * 0.5) / E_**2
    print("margin +/-", int(E_*100), "% -> need", ceil(n), "people")
print()
print("population size is not in the formula.")
print("1,000 people tells you as much about India as about Iceland.")

Null and alternative hypothesis

Why it exists

The structure of every test. It is a criminal trial, and the match is exact.

In short

NULL (H0) is the boring position: no difference, nothing going on. Assumed true until the evidence forces you off it - like 'innocent'. ALTERNATIVE (H1) is what you would have to prove.

print("H0  the null         : Tech and HR are paid the same")

The p-value

Why it exists

The number every test reports. Misreading it is the most common error in applied statistics.

In short

The probability of seeing data at least this extreme IF the null were true. It is a statement about the DATA, computed in a world where nothing is going on - not a probability about your hypothesis.

Code
sample = pop.sample(100, replace=True, random_state=54)
t, p = stats.ttest_1samp(sample, 65000)
print("sample average:", round(sample.mean()), " claim: 65000")
print("p-value       :", round(p, 4))
print()
print("reads as: IF the true average really were 65,000,")
print("a sample like ours would almost never happen. so REJECT 65,000.")
print("(0.0000 is rounding - the p-value is tiny, never exactly zero.)")
Output
sample average: 72149 claim: 65000 p-value : 0.0 reads as: IF the true average really were 65,000, a sample like ours would almost never happen. so REJECT 65,000. (0.0000 is rounding - the p-value is tiny, never exactly zero.)

What a p-value is NOT

Why it exists

These two sentences get written in real reports and they are both wrong.

In short

p = 0.03 does NOT mean '3% chance the null is true', and NOT '97% chance my finding is real'. Same trap as confidence intervals: the probability belongs to the random thing (the data), never the fixed thing (the hypothesis).

Code
print("p = 0.03 means:")
print("  IF nothing were going on, data this extreme happens 3% of the time")
print()
print("it does NOT mean:")
print("  '3% chance the null is true'")
print("  '97% chance my finding is real'")
Output
p = 0.03 means: IF nothing were going on, data this extreme happens 3% of the time it does NOT mean: '3% chance the null is true' '97% chance my finding is real'

The 0.05 threshold

Why it exists

Knowing it is a convention, not a law, is part of using it honestly.

In short

Somebody has to draw a line for 'surprising enough'. 0.05 is where most fields settled, suggested about a hundred years ago. Particle physics uses about 1 in 3.5 million. 0.049 and 0.051 are the same result.

print("0.05 is a CONVENTION, not a law of nature.")

Fail to reject is not proved

Why it exists

Never write 'accept the null'. It is the single most common way to lose marks on an otherwise correct answer, and it misstates what the test did.

In short

A high p-value means the evidence was not strong enough - not that there is nothing there. A tiny sample fails to reject almost anything. 'Not guilty' is a verdict about the evidence, not a certificate of innocence.

Code
sample = pop.sample(100, replace=True, random_state=54)

Type I and Type II errors

Why it exists

Explains why running lots of tests is dangerous, and why small samples miss real effects.

In short

TYPE I: you say there is a difference and there is not - crying wolf. Happens 5% of the time BY DESIGN at p<0.05. TYPE II: a real difference exists and you miss it, almost always because the sample was too small.

Code
print("Type I  - convict the innocent. 5% of the time, by design.")
print("Type II - let the guilty go. usually too small a sample.")
print()
print("a real 6,000 difference, three sample sizes:")
import numpy as np
rng = np.random.default_rng(0)
for n in (10, 30, 200):
    a = rng.normal(70000, 16000, n); b = rng.normal(76000, 16000, n)
    p = stats.ttest_ind(a, b)[1]
    print("   n =", n, " p =", round(p,4), " ->", "found it" if p<0.05 else "MISSED IT")
Output

Why it exists

The habit that separates an analyst people trust from one they do not.

In short

At a 5% threshold, one test in twenty comes back significant when nothing is there - by design. Test everything against everything and you WILL find something. It will not be real.

import numpy as np

Probability basicsDay 8

The two ways to get a probability

Why it exists

Knowing which one you are in. It is easy to assume probability means dice and coins; at work it is almost always counting rows.

In short

THEORETICAL: reason from the structure of the thing - a coin has 2 sides, so heads is 1/2. EMPIRICAL: count what actually happened - 49 of 201 work in Tech, so 0.244.

Code
print("theoretical: a coin has 2 sides      -> P(heads) = 0.5")
print("empirical  : count the actual rows   -> P(Tech)  =",
      round((df['department'] == 'Tech').mean(), 3))
print()
print("note it is 0.244, NOT 0.25 - the four departments are different sizes")
Output
theoretical: a coin has 2 sides -> P(heads) = 0.5 empirical : count the actual rows -> P(Tech) = 0.244 note it is 0.244, NOT 0.25 - the four departments are different sizes

The scale, and the complement rule

Why it exists

The complement rule turns horrible calculations into one line. Worth knowing purely for that.

In short

Every probability sits between 0 and 1, and all the pieces sum to 1. So the chance of something NOT happening is 1 minus the chance it does.

Code
p = df['department'].value_counts(normalize=True)
print(p.round(3))
print("total:", p.sum())
print()
print("P(not Tech) = 1 -", round(p['Tech'],3), "=", round(1 - p['Tech'], 3))
Output
department Sales 0.323 Tech 0.244 HR 0.224 Marketing 0.209 Name: proportion, dtype: float64 total: 1.0 P(not Tech) = 1 - 0.244 = 0.756

The OR rule

Why it exists

Stops you double-counting, which is the most common arithmetic slip in this topic.

In short

P(A or B) = P(A) + P(B) - P(A and B). You subtract the overlap because anyone in both groups got counted twice.

Code
t = df['department'] == 'Tech'
e = df['rating'] == 'Excellent'
print("P(Tech)         :", round(t.mean(), 3))
print("P(Excellent)    :", round(e.mean(), 3))
print("just added      :", round(t.mean() + e.mean(), 3), " <- too big")
print("actually        :", round((t | e).mean(), 3))
print("because", (t & e).sum(), "people are in BOTH and got counted twice")
Output
P(Tech) : 0.244 P(Excellent) : 0.244 just added : 0.488 <- too big actually : 0.423 because 13 people are in BOTH and got counted twice

The AND rule, and its condition

Why it exists

The condition is the part everyone forgets, and forgetting it gives wrong answers.

In short

P(A and B) = P(A) x P(B), but ONLY if the two do not affect each other. Always check by multiplying and comparing against the real count.

Code
t  = df['department'] == 'Tech'
e  = df['rating'] == 'Excellent'
hi = df['salary'] > df['salary'].median()

print("Tech & Excellent : actual", round((t & e).mean(), 3),
      " predicted", round(t.mean()*e.mean(), 3), " -> works")
print("Tech & well paid : actual", round((t & hi).mean(), 3),
      " predicted", round(t.mean()*hi.mean(), 3), " -> FAILS")
Output
Tech & Excellent : actual 0.065 predicted 0.059 -> works Tech & well paid : actual 0.189 predicted 0.12 -> FAILS

Mutually exclusive vs independent

Why it exists

These two get merged in every exam. They are close to opposites.

In short

MUTUALLY EXCLUSIVE: both cannot happen - you cannot be in HR and Tech. INDEPENDENT: one tells you nothing about the other. If two things are mutually exclusive, knowing one tells you the other is impossible, which is total information - the opposite of independent.

Code
print("P(HR and Tech) =", ((df['department']=='HR') & (df['department']=='Tech')).sum(),
      " -> mutually exclusive")

Conditional probability

Why it exists

The shape almost every real question comes in - not 'will a customer buy' but 'will a customer WHO CLICKED THE AD buy'.

In short

P(A | B) is the chance of A given B is already true. The bar means 'given', not divide. To do it: throw away every row where B is false, then count normally. It is a filter.

print("P(Tech)             :", round((df['department']=='Tech').mean(), 3))

P(Excellent) : 0.244 P(Excellent | Tech) : 0.265 barely moved -> department tells you nothing about rating P(Tech) : 0.244 P(Tech | well paid) : 0.384 jumped -> salary DOES tell you about department

P(A|B) is not P(B|A)

Why it exists

Getting this backwards is how confident, expensive, wrong decisions get made.

In short

The two directions are different questions with different answers. Same people on top of both fractions - only the denominator changes.

Code
med  = df['salary'].median()
tech = df[df['department']=='Tech']
hi   = df[df['salary'] > med]

print("P(Tech | well paid) =", both, "/", len(hi), "=", round(both/len(hi), 3))
print("P(well paid | Tech) =", both, "/", len(tech), "=", round(both/len(tech), 3))
print()
print("same", both, "people on top. only the bottom changed. answer doubled.")
print()
print("'most food poisoning victims ate out'  - true")

Output

Getting started

The equals sign

In short

A cell holds either a value or a formula. Anything starting with = is a formula and is worked out; anything else is stored as typed.

Code
38            a value
=20+18        a formula, shows 38
=K5           an address, shows whatever K5 holds

A range, with a colon

In short

The colon means THROUGH. K2:K201 is every cell from K2 down to K201.

Code
=SUM(K2:K201)
Output
18,974,273

COUNT and COUNTA

In short

COUNT only counts numbers. COUNTA counts anything that is not empty, including text.

Code
=COUNTA(C2:C201)      names
=COUNT(I2:I201)       ages
=COUNT(K2:K201)       salaries
Output
200 199 198

COUNTBLANK

In short

Counts the empty cells in a range. The gap between COUNTA and COUNT is the same information.

Code
=COUNTBLANK(K2:K201)
Output
2

SUM, AVERAGE, MEDIAN

In short

AVERAGE skips blank cells rather than treating them as zero, so it divides by 198 here, not 200.

Code
=SUM(K2:K201)
=AVERAGE(K2:K201)
=MEDIAN(K2:K201)
Output
18,974,273 95,829.66 68,841

MIN and MAX

In short

The smallest and largest value in a range. A quick way to spot a value that cannot be real.

Code
=MIN(I2:I201)         youngest
=MAX(I2:I201)         oldest
Output
-4 210

Mean against median

In short

When the two disagree by a lot, one extreme value is pulling the average. Here the gap is about 27,000.

Code
=AVERAGE(K2:K201)
=MEDIAN(K2:K201)
=AVERAGE(K2:K201)-MEDIAN(K2:K201)
Output
95,829.66 68,841 26,988.66

Absolute references

Relative by default

In short

Copying a formula down shifts every reference down with it. Usually that is what you want.

Code
M2    =K2-Q10
      fill down
M3    =K3-Q11      <-- Q11 moved too, and is empty

The dollar sign locks it

In short

$Q$10 stays at Q10 however far the formula is copied. $Q locks the column, $10 locks the row.

Code
M2    =K2-$Q$10
      fill down
M3    =K3-$Q$10      <-- stayed put

Why it matters

In short

Without the dollars the column quietly becomes a copy of the one beside it. Nothing turns red.

Code
=K2-Q10       wrong, and looks plausible
=K2-$Q$10     right

Conditions

IF

In short

One test, two answers. The test comes first, then what to show when it is true, then when it is false.

Code
=IF(K2>$Q$5, "Above average", "Below average")

IFS

In short

More than two outcomes. Excel checks the conditions in order and stops at the first true one, so order matters.

Code
=IFS(H2<=2, "Junior", H2<=7, "Mid", H2>=0, "Senior")

COUNTIF

In short

Counts the cells in a range that meet one condition.

Code
=COUNTIF(D2:D201, "Tech")
Output
49

SUMIF

In short

Range to test, the condition, then the range to add up. Three arguments, in that order.

Code
=SUMIF(D2:D201, "Tech", K2:K201)
Output
9,108,170

AVERAGEIF

In short

The same shape as SUMIF. It also skips blanks, so the divisor may be smaller than the headcount.

Code
=AVERAGEIF(D2:D201, "HR", K2:K201)
=AVERAGEIF(D2:D201, "Tech", K2:K201)
Output
56,705.14 189,753.54

COUNTIFS — two conditions

In short

Pairs of range and condition. Every pair must be true for the row to count.

Code
=COUNTIFS(D2:D201, "Tech", K2:K201, ">50000")
Output
48

A condition built from a cell

In short

To compare against a value in a cell, put the operator in quotes and join it with &.

Code
=COUNTIF(K2:K201, ">"&$Q$5)      above the average in Q5
=COUNTIF(K2:K201, "<"&$Q$5)      below it
Output
12 186

The counts will not always add up

In short

12 above and 186 below is 198, not 200. The two blank salaries are neither, and COUNTIF simply skips them.

Code
=COUNTIF(K2:K201, ">"&$Q$5) + COUNTIF(K2:K201, "<"&$Q$5)
Output
198

Lookups

VLOOKUP

In short

What to look for, where to look, which column to bring back, and exact or approximate. Four arguments.

Code
=VLOOKUP(G2, bonus!$A$2:$B$5, 2, FALSE)

Always FALSE

In short

The fourth argument is optional, and leaving it out gives approximate matching, silently and wrongly. Type FALSE every time.

Code
=VLOOKUP(G2, bonus!$A$2:$B$5, 2, FALSE)      exact
=VLOOKUP(G2, bonus!$A$2:$B$5, 2)             approximate - avoid

Lock the lookup table

In short

Without the dollar signs the table slides down as you fill the formula, and rows start returning #N/A.

Code
=VLOOKUP(G2, bonus!$A$2:$B$5, 2, FALSE)      locked
=VLOOKUP(G2, bonus!A2:B5,     2, FALSE)      slides - wrong

#N/A means not found

In short

It is a sentence, not a crash: the value you asked for is not in the table you pointed at. Often a data problem rather than a formula one.

Code
=VLOOKUP("Outstanding", bonus!$A$2:$B$5, 2, FALSE)
Output
#N/A

IFERROR

In short

Replaces an error with something readable. It hides the error; it does not fix the missing data.

Code
=IFERROR(VLOOKUP(G2, bonus!$A$2:$B$5, 2, FALSE), "Not found")

VLOOKUP only looks right

In short

The value you search for must be in the first column of the range. It cannot return anything to the left of it.

Code
VLOOKUP searches column 1 of the range and returns a column to its RIGHT.
To look left, use INDEX + MATCH or XLOOKUP.

INDEX and MATCH

In short

MATCH finds the position, INDEX returns the value at that position. Together they look in any direction.

Code
=MATCH("Karthik Reddy", C2:C201, 0)        the position
=INDEX(A2:A201, 3)                        the value there
=INDEX(A2:A201, MATCH("Karthik Reddy", C2:C201, 0))

XLOOKUP

In short

Replaces all of the above. What to find, where to look, what to return, and what to show if nothing matches.

Code
=XLOOKUP(G2, bonus!$A$2:$A$5, bonus!$B$2:$B$5, "Not found")
